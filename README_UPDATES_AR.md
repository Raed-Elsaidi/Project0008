# Project06 — التحديثات الأخيرة

تم تحديث المشروع ليشمل:

- فتح دخول الطالب قبل موعد الامتحان بـ **5 دقائق**.
- بعد تسجيل الدخول: التحقق من رقم الجلوس وكلمة المرور ثم التحقق من الوجه.
- بعد نجاح التحقق من الوجه: يظهر **عدّ تنازلي لوقت بدء الامتحان**.
- لا يتم تفعيل زر دخول الامتحان إلا عند حلول وقت البداية.
- التحقق المستمر من الوجه أثناء الامتحان أصبح كل **5 دقائق** بدل 20 ثانية.
- استبدال `window.alert` برسائل Toast في وسط الشاشة تختفي بعد ثانيتين.
- رسائل الخطأ في شاشة الدخول والتسجيل والامتحان أصبحت مركزية ومؤقتة.
- إضافة أيقونة بنك الأسئلة الجديدة إلى شاشة الخدمات الرئيسية.
- الحفاظ على نماذج Face Recognition داخل `public/models`.
- الحفاظ على Footer وروابط التواصل وهوية RAED ELSAIDI.

## التشغيل

بعد فك الضغط داخل مجلد المشروع:

```bash
npm install
npm run dev
```

لا تعتمد على `node_modules` المنقول من جهاز آخر؛ يجب تشغيل `npm install` على جهاز التشغيل حتى يتم تنزيل الحزم الأصلية الخاصة بنظام التشغيل.


### تحديث التحكم بوصول الامتحان
- تم الإبقاء على `exams.is_active`.
- تمت إضافة `exams.access_enabled` كمفتاح تفعيل/تعطيل إداري مستقل.
- السماح للطالب بالوصول يتطلب `is_active = true` **و** `access_enabled = true`، بالإضافة إلى تطابق الفرع والتاريخ والوقت وقاعدة الدخول قبل 5 دقائق.
- عند إنشاء امتحان جديد: `is_active = true` و`access_enabled = false`، لذلك يكون الامتحان معطلاً حتى يفعّله المدير.

- الموقع لا يستطيع إيقاف إشعارات نظام الهاتف/Windows الأخرى؛ ذلك يتطلب تطبيقًا أصليًا أو Kiosk مع صلاحيات نظام التشغيل.

## 🔐 أمان كلمات المرور - آخر تحديث
- سياسة كلمات المرور الجديدة: من 8 إلى 10 أحرف، مع حرف إنجليزي صغير وكبير ورقم ورمز.
- طلاب النظام والموظفون والمشرفون يستخدمون bcrypt بتكلفة 8 (bcrypt cost=8) داخل PostgreSQL عبر pgcrypto.
- كلمات المرور القديمة المخزنة كنص صريح تتحول إلى bcrypt عند تشغيل migration 003.
- التحقق من تسجيل الدخول يتم داخل قاعدة البيانات ولا يعيد hash إلى الواجهة.
- لا يتم إرسال كلمات المرور المحفوظة في قاعدة البيانات عبر البريد؛ يجب إعطاء كلمة المرور الجديدة للموظف وقت إنشائها أو تغييرها.
- شغّل `database_migrations/003_password_security.sql` بعد أخذ نسخة احتياطية.
